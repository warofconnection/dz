# Clinic8: один сценарий сборки для Packet Tracer 8.2.2

## Статус и границы проверки

Использовать **`clinic8-all-in-one.js`**. Старые режимы «113 устройств / ноль кабелей» заменены одним сценарием. Файлы `build-clinic8.js` и `finish-clinic8.js` содержат тот же код для совместимости, но **не должны одновременно импортироваться в один модуль**.

Сценарий подготовлен по API из официального установщика Cisco 8.2.2. Проверены синтаксис, соответствие используемых операций документации и управление этапами на тестовых заменах IPC: новый проект, частичная сеть, повторный запуск, сохранение постороннего устройства, строковые числа/флаги, раздельные имена/номера портов, числовые IPv4-адреса, пути Windows и обнаружение ошибок кабеля, IOS, DHCP, HTTP, почты, гостевого доступа и сохранения. **Это не испытания в Cisco.** В облаке Packet Tracer запускается, но остаётся на обязательном окне входа. Нельзя гарантировать успешный прогон в Cisco до его фактического выполнения.

## Запуск в существующем зарегистрированном модуле

1. Остановить старый модуль кнопкой **Stop**. Текущую сеть сохранить обычным **File → Save As**. Сценарий можно выполнять в пустой или частично созданной сети: нужные устройства ищутся по именам, недостающие создаются. Посторонние устройства не удаляются.
2. Открыть **Configure PT Script Modules → Clinic8 Builder → Edit**. В **General → Security Privileges** включить ровно семь разрешений:
   - **Application** — доступ к рабочему полю;
   - **Get Network Info**;
   - **Change Network Info**;
   - **Change User Interface**;
   - **Miscellaneous UI**;
   - **File Operations** — сохранить новый `.pkt`;
   - **IPC** — остановить собственный модуль после завершения или ошибки.
3. В **Script Engine** удалить из этого модуля все старые `.js`, включая исходный `main.js`, если он есть. Импортировать **только `clinic8-all-in-one.js`**. Это удаление файлов скрипта из модуля, а не устройств сети.
4. Сохранить модуль через **Info → Save**. Если Save недоступен: **Info → 6. Saving → Export** в `.pts`, затем удалить старую регистрацию из Configure PT Script Modules и добавить обновлённый `.pts` через Add. Не запускать старую и новую версии одновременно.
5. Открыть **Debug**, нажать **Start** один раз. Сборка идёт по таймерам, поэтому сообщения появляются постепенно. Часть испытаний ждёт ответы сети; весь сценарий может занять несколько минут.
6. Успех подтверждается сообщением **`SAVED: <путь к файлу>`**. Файл называется `clinic8-v3-<метка-времени>.pkt` и сохраняется в стандартную папку Packet Tracer под новым именем. Затем модуль останавливает себя. Если сообщение начинается с **`ERROR:`**, прогон не завершён — созданная сеть сохраняется для диагностики; текст содержит этап и причину.

## Что происходит

- По именам разрешаются 113 основных устройств: 99 оконечных устройств поликлиники, 11 её маршрутизаторов/коммутаторов, 2 устройства оператора и внешний сервер.
- Создаются ещё 4 гостевых **TabletPC-PT** для проверки беспроводных сегментов: всего **117 проектных устройств**. Глобальное число устройств не используется как условие запуска; оно может включать посторонние устройства.
- Все требуемые порты проверяются до создания кабелей. Проводные соединения: 112. Явно выбирается прямой/перекрёстный Ethernet. Уже существующий правильный кабель определяется по одному UUID на обоих концах. Занятый неправильным кабелем порт вызывает остановку без удаления чужого соединения.
- IOS применяет VLAN, trunks, маршруты, DHCP, гостевые ACL и NAT; проверяется возвращаемый статус каждой команды. Завершённые конфигурации помечаются версией, чтобы повторный запуск их не дублировал.
- Статические адреса назначаются серверам и принтерам; рабочие ПК и гости получают DHCP.
- Включаются HTTP, внутренний/внешний DNS, SMTP/POP3 и четыре почтовых клиента; четыре точки доступа и гостевые планшеты используют WPA2-PSK.
- Выполняются ожидание адресов в нужных подсетях, 8 положительных HTTP-проверок, SMTP-доставка и POP3-получение двух уникальных писем; для каждого гостя проверяются ранее успешный внешний HTTP, отсутствие страницы МИС за 15 секунд и наличие запрещающего ACL.
- `.pkt` сохраняется под новым именем; временная техническая надпись прогресса удаляется из схемы до сохранения. Никакие реальные пароли не читаются и вход Cisco не автоматизируется.

## Учебные значения

Wi-Fi: SSID `Clinic8-C1-Guest`, `Clinic8-C2-Guest`, `Clinic8-B1-Guest`, `Clinic8-B2-Guest`. Пароль только для искусственной модели: `Clinic8-Lab-2026`.

Почта: `c1@clinic8.test`, `c2@clinic8.test`, `b1@clinic8.test`, `b2@clinic8.test`; тот же учебный пароль. Это не действующие учётные записи. Для реального внедрения такие значения использовать нельзя.

## Что остаётся для сдачи

Успешный сценарий подтверждает только перечисленные проверки в конкретном прогоне Packet Tracer. После получения `.pkt` нужно отдельно проверить повторное открытие, сохранить настоящий скриншот схемы и журнал испытаний, обновить слайд 13 и снять черновой статус отчёта после закрытия остальных требований. Симулятор не проверяет настоящую МИС/PACS, производительность реальных маршрутизаторов, VPN или соответствие медицинской сети законодательству.

## Почему предыдущие попытки не завершились

Первому варианту не хватало Application для `getLogicalWorkspace`; затем он остановился на первом кабеле. Причина возврата false для кабеля без фактических моделей/портов не была доказана. Второй вариант требовал ровно 113 устройств и ноль кабелей; такое условие слишком ограничивало восстановление и не помогало выяснить реальный состав сети. В новой версии нет этого условия, перечисляются фактические устройства/порты и проверяется реальный результат каждой стадии.
