# Автоматическая сборка в авторизованном Packet Tracer 8.2.2

## Статус

`build-clinic8.js` подготовлен по официальной документации IPC и Script Modules, которая входит в установщик Cisco Packet Tracer 8.2.2. Синтаксис ECMAScript проверен, входные данные согласованы. **Исполнение в Packet Tracer не проверено:** облачная программа запускается, но требует вход Cisco. Скрипт предназначен для обычного запуска в уже авторизованной программе; он не выполняет вход и не изменяет систему авторизации.

113 устройств = 99 оконечных устройств поликлиники + 5 её маршрутизаторов + 6 её коммутаторов + 2 устройства оператора + 1 внешний сервер. 112 проводных соединений. Гостевые ноутбуки для испытаний Wi-Fi добавляются отдельно.

## Подготовка

Скачать ветку `its-variant8-draft` через Code → Download ZIP, распаковать. Открыть Packet Tracer и войти обычным способом, если программа требует вход. Не присылать пароли или файлы сеанса.

## Запуск

1. Создать **новый пустой** проект: File → New. Существующую свою работу сначала сохранить. Скрипт отказывается начинать в непустой сети; созданные при ошибке устройства сам не удаляет.
2. Открыть **Extensions → Scripting → New PT Script Module**. В General задать Name `Clinic8 Builder`, ID `ru.clinic8.builder`. Поля Password и Publisher Signing оставить пустыми.
3. В нижней части General → Security Privileges разрешить просмотр и изменение сети, просмотр и изменение GUI. Другие привилегии не включать. Если названия/набор флажков отличаются, сохранить скриншот окна для уточнения.
4. В **Script Engine** удалить только исходные файлы нового пустого модуля, затем **Import** → выбрать `build-clinic8.js` из распакованной папки `packet-tracer`.
5. Нажать **Start**. Не нажимать Run File вместо Start: функция `main()` вызывается при старте модуля. Дождаться завершения; при ошибке открыть **Debug**, скопировать текст ошибки и сделать скриншот сети. Не объявлять частичную сборку успешной и не повторять запуск поверх созданных устройств.
6. Если все 113 устройств появились, сохранить **File → Save As → clinic8.pkt**. Статус сборки ещё не означает успешных функциональных испытаний.

## Что скрипт выполняет

- Создаёт устройства с проектными именами и размещением по этажам.
- Создаёт соединения по портовой ведомости.
- Добавляет подписи площадок и отделов.
- Передаёт команды подготовленных IOS-конфигураций через документированный `CiscoDevice.enterCommand`.
- Запрашивает DHCP на ПК, задаёт статические адреса принтерам и серверам.
- Не читает пароли, не подключается к Интернету, не меняет существующую сеть и не выполняет команды операционной системы.

## Что остаётся после сборки

Настроить GUI-службы HTTP, DNS, EMAIL и Wi-Fi по `ASSEMBLY.md`, проверить сообщения IOS на каждом устройстве, выполнить приёмочные проверки и сохранить фактические результаты. В частности, штатные имена моделей, преобразование возвращаемого статуса API и применение DHCP должны быть проверены на конкретной установленной версии, поэтому ошибки скрипта требуют диагностики, а не ручного объявления успеха.

Скриншот и сохранённый `.pkt` можно передать для дальнейшей проверки; доступ к файлу не заменяет возможность запустить симулятор в облаке. Если облачный вход остаётся недоступен, фактические проверки придётся выполнять в авторизованной программе на компьютере пользователя, с фиксацией результатов.
