# Автоматическая сборка в авторизованном Packet Tracer 8.2.2

## Статус

`build-clinic8.js` подготовлен по официальной документации IPC и Script Modules, которая входит в установщик Cisco Packet Tracer 8.2.2. Синтаксис ECMAScript проверен, входные данные согласованы. **Исполнение в Packet Tracer не проверено:** облачная программа запускается, но требует вход Cisco. Скрипт предназначен для обычного запуска в уже авторизованной программе; он не выполняет вход и не изменяет систему авторизации.

113 устройств = 99 оконечных устройств поликлиники + 5 её маршрутизаторов + 6 её коммутаторов + 2 устройства оператора + 1 внешний сервер. 112 проводных соединений. Гостевые ноутбуки для испытаний Wi-Fi добавляются отдельно.

## Подготовка

Скачать ветку `its-variant8-draft` через Code → Download ZIP, распаковать. Открыть Packet Tracer и войти обычным способом, если программа требует вход. Не присылать пароли или файлы сеанса.

## Запуск

1. Создать **новый пустой** проект: File → New. Существующую свою работу сначала сохранить. Скрипт отказывается начинать в непустой сети; созданные при ошибке устройства сам не удаляет.
2. Открыть **Extensions → Scripting → New PT Script Module**. В General задать Name `Clinic8 Builder`, ID `ru.clinic8.builder`. Поля Password и Publisher Signing оставить пустыми.
3. В нижней части General → Security Privileges включить пять флажков: **Application**, **Get Network Info**, **Change Network Info**, **Change User Interface**, **Miscellaneous UI**. **Application** нужен для `Workspace.getLogicalWorkspace`; это подтверждено таблицей регистрации IPC в поставленном пользователем Packet Tracer 8.2.2. Остальные оставить выключенными.
4. В **Script Engine** удалить только исходные файлы нового пустого модуля, затем **Import** → выбрать `build-clinic8.js` из распакованной папки `packet-tracer`.
5. Перейти во вкладку **Info**, прокрутить вниз до раздела **6. Saving**, нажать **Export** и сохранить весь модуль как `Clinic8Builder.pts`. Это не кнопка Export во вкладке Script Engine: там экспортируется только JavaScript-файл. Закрыть окно редактора.
6. Открыть **Extensions → Scripting → Configure PT Script Modules**, нажать **Add** и выбрать сохранённый `Clinic8Builder.pts`. Выделить добавленный модуль и открыть **Edit**, затем вкладку **Script Engine**.
7. Нажать **Start**. Не нажимать Run File вместо Start: функция `main()` вызывается при старте модуля. Дождаться завершения; при ошибке открыть **Debug**, скопировать текст ошибки и сделать скриншот сети. Не объявлять частичную сборку успешной и не повторять запуск поверх созданных устройств.
8. Если все 113 устройств появились, сохранить **File → Save As → clinic8.pkt**. Статус сборки ещё не означает успешных функциональных испытаний.

Если модуль уже добавлен и ошибка сообщает об отсутствии привилегии `getLogicalWorkspace`, откройте его через Configure PT Script Modules → Edit, отметьте Application в General и сохраните весь модуль через Info → Save. Если Save недоступен, экспортируйте обновлённый .pts, удалите старую регистрацию модуля из списка и добавьте обновлённый .pts заново. Устройства при этой ошибке ещё не созданы.

## Что скрипт выполняет

- Создаёт устройства с проектными именами и размещением по этажам.
- Создаёт соединения по портовой ведомости.
- Добавляет подписи площадок и отделов.
- Передаёт команды подготовленных IOS-конфигураций через документированный `CiscoDevice.enterCommand`.
- Запрашивает DHCP на ПК, задаёт статические адреса принтерам и серверам.
- Не читает пароли, не подключается к Интернету, не меняет существующую сеть и не выполняет команды операционной системы.

## Что остаётся после сборки

Настроить GUI-службы HTTP, DNS, EMAIL и Wi-Fi по `ASSEMBLY.md`, проверить сообщения IOS на каждом устройстве, выполнить приёмочные проверки и сохранить фактические результаты. В частности, штатные имена моделей, преобразование возвращаемого статуса API и применение DHCP должны быть проверены на конкретной установленной версии, поэтому ошибки скрипта требуют диагностики, а не ручного объявления успеха.

Скриншот и сохранённый `.pkt` можно передать для дальнейшей проверки; доступ к файлу не заменяет возможность запустить симулятор в облаке. Если облачный вход остаётся недоступен, фактические проверки придётся выполнять в авторизованной программе на компьютере пользователя, с фиксацией результатов.

## Продолжение после ошибки первого кабеля

Если появился `Failed link: SW-C1A / FastEthernet0/1 / C1-PC01 / @ETH`, первоначальный скрипт оборвался до первого кабеля. В исправленной версии вместо AUTO явно выбираются Ethernet Straight-Through (8100) и Cross-Over (8101). Это диагностика возможной причины; успешное исполнение должно быть подтверждено в Packet Tracer.

Для сохранения уже созданных устройств:

1. Остановить модуль кнопкой Stop и сохранить текущую сеть как `clinic8-devices.pkt`.
2. Скачать обновлённый `packet-tracer/finish-clinic8.js`.
3. В зарегистрированном модуле открыть Script Engine, удалить **только старый JS-файл из модуля** и импортировать `finish-clinic8.js`. Старый `main()` не должен оставаться в другом файле этого модуля.
4. Сохранить модуль через Info → Save. Если Save недоступен, экспортировать обновлённый .pts и перерегистрировать его. Сеть при этом не удалять.
5. Нажать Start. Скрипт разрешает продолжение только при 113 ожидаемых устройствах и нуле существующих кабелей. После частичного создания кабелей повторный запуск запрещается, чтобы не менять имеющуюся сеть.

Модуль не обязан сам переходить в Stopped после выполнения `main()`: Script Module продолжает существовать до Stop. Для проверки результата в Debug вычислить `BUILD_COMPLETE`: только `true` означает, что скрипт дошёл до конца и проверил 112 кабелей. Это не означает, что HTTP, DNS, EMAIL и Wi-Fi уже проверены. При ошибке прислать её полностью: новая версия включает выбранные порты, модели и тип кабеля.
